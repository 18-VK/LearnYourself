# Git Basics: Core Commands and Concepts

This file contains the most important beginner-friendly Git commands and the mental model behind them.

---

## 1. Git config

### Purpose
Configure Git identity, editor behavior, aliases, and project preferences.

### Common commands

```bash
git config --global user.name "Your Name"
git config --global user.email "you@example.com"
git config --global core.editor "code --wait"
```

### Why it matters
- Git stores author information in every commit.
- The editor is used when Git opens a commit message editor.
- Global config applies to all repositories on your machine.

### Example

```bash
git config --global user.name "Aman Kumar"
git config --global user.email "aman@gmail.com"
```

### Important note
`user.name` and `user.email` are not login credentials. They are metadata stored inside commits.

## 2. git init

### Purpose
Initialize a new Git repository in the current folder.

### Syntax

```bash
git init
```

### Example

```bash
mkdir my-project
d:
cd my-project
git init
```

### What it does
Creates a `.git` folder that contains Git’s internal data.

### Use case
Start tracking an existing project locally.

---

## 3. git clone

### Purpose
Copy an existing remote repository to your local machine.

### Syntax

```bash
git clone <repository-url>
```

### Example

```bash
git clone https://github.com/user/my-repo.git
```

### Use case
Get a copy of a project that already exists on GitHub/GitLab/Bitbucket.

---

## 4. git status

### Purpose
Show the current state of the repository.

### Syntax

```bash
git status
```

### What it shows
- modified files
- staged files
- untracked files
- branch name

### Example output

```bash
On branch main
Your branch is up to date with 'origin/main'.

Changes not staged for commit:
  modified:   app.js

Untracked files:
  notes.txt
```

---

## 5. git add

### Purpose
Move changes from the working directory to the staging area.

### Syntax

```bash
git add <file>
git add .
git add -A
git add -p
```

### Examples

```bash
git add app.js
git add .
git add -A
```

### Difference between `git add .` and `git add -A`

| Command | Scope |
| --- | --- |
| `git add .` | Stages changes in the current directory and below |
| `git add -A` | Stages all changes in the repo |

### Use case
Prepare files for the next commit.

---

## 6. git commit

### Purpose
Create a snapshot of the staged changes.

### Syntax

```bash
git commit -m "message"
git commit
```

### Example

```bash
git commit -m "Add login page"
```

### Notes
- `-m` is the shortcut for writing a commit message inline.
- If you run `git commit` without `-m`, Git opens your editor.

### Good commit message format

```bash
Fix login validation bug
```

### Example of a bad message

```bash
changes
```

---

## 7. git diff

### Purpose
Show the difference between versions of files.

### Syntax

```bash
git diff
git diff --staged
git diff HEAD
git diff main feature/login
```

### Examples

```bash
git diff
git diff --staged
git diff HEAD~1 HEAD
```

### When to use it
- before committing
- before pushing
- to review the actual code changes

---

## 8. git restore

### Purpose
Discard or undo changes.

### Syntax

```bash
git restore <file>
git restore --staged <file>
```

### Examples

```bash
git restore app.js
git restore --staged app.js
```

### Use cases
- undo local edits
- unstage files without deleting content

### Important difference
- `git restore <file>` = discard working tree changes
- `git restore --staged <file>` = unstage only

---

## 9. Working tree, staging area, and repository

### 1) Working tree
Files currently in your project folder. This is where you edit code.

### 2) Staging area
A temporary area where you choose what gets included in the next commit.

### 3) Repository
Git stores committed history in `.git/objects`.

### Simple model

```text
Working directory -> git add -> Staging area -> git commit -> Repository
```

---

## 10. .git folder

### Purpose
The `.git` folder is Git’s internal database and configuration store.

### Important fact
If you delete `.git`, you lose the repository history.

### Common internal contents

```text
.git/
  config
  HEAD
  objects/
  refs/
  index
  logs/
```

## 11. Line endings: CRLF vs LF

### Why this matters
Different operating systems use different line endings.

| OS | Line ending |
| --- | --- |
| Windows | CRLF (`\r\n`) |
| Linux/macOS | LF (`\n`) |

### Recommended settings

#### Windows
```bash
git config --global core.autocrlf true
```

#### Linux/macOS
```bash
git config --global core.autocrlf input
```

### Avoid this unless necessary

```bash
git config --global core.autocrlf false
```

This can create noisy diffs and team conflicts.

---

## 12. Common mistakes to avoid

- forgetting `--wait` after setting VS Code as editor
- mixing CRLF and LF line endings in the same repo
- committing without checking `git status`
- using wrong Git identity (`user.name` / `user.email`)
- pushing without checking branch state

---

## 13. Quick reference

```bash
git init
git clone <url>
git status
git add .
git commit -m "message"
git diff
git restore <file>
git restore --staged <file>
```

This is the minimal set of commands every beginner should know first.

---

## 14. Beginner workflow

```bash
git status
git add .
git commit -m "Add feature"
git push origin main
```

This is the basic everyday Git cycle.
