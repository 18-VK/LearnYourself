# Common Table Expressions (CTEs)

Common Table Expressions (CTEs) are a very important SQL concept used for query readability, modular queries, recursion, and window-function workflows.
A Common Table Expression (CTE) is a temporary named result set defined within a query.

It exists only for the duration of that query.

**Syntax:**

```sql
WITH CTE_Name AS
(
    SELECT ...
)
SELECT *
FROM CTE_Name;
```

**Key points:**

- Defined using `WITH`
- Used immediately in the following query
- Improves readability compared to nested subqueries

CREATE TABLE Employees (

# Example

**Goal:** Get employees with salary above department average.

## Simple CTE Example

```sql
WITH DeptAvg AS
(
    SELECT Department,
           AVG(Salary) AS AvgSalary
    FROM Employees
    GROUP BY Department
)
SELECT e.Name, e.Department, e.Salary
FROM Employees e
JOIN DeptAvg d
ON e.Department = d.Department
WHERE e.Salary > d.AvgSalary;
```

**Result**

| Name | Department | Salary |
| ---- | ---------- | ------ |
| Aman | IT         | 60000  |

## CTE vs Subquery

**Subquery version:**

```sql
SELECT Name, Department, Salary
FROM Employees
WHERE Salary >
(
    SELECT AVG(Salary)
    FROM Employees e2
    WHERE e2.Department = Employees.Department
);
```

**CTE version:**

Cleaner and easier to maintain.

## Subquery with JOIN followed by 'GROUP BY'

For large tables, a JOIN with `GROUP BY` can sometimes perform better than a correlated subquery:

```sql
SELECT e.*
FROM Employees e
JOIN (
    SELECT DepartmentId, AVG(Salary) AS AvgSalary
    FROM Employees
    GROUP BY DepartmentId
) d ON e.DepartmentId = d.DepartmentId
WHERE e.Salary > d.AvgSalary;
```

# Correlated subquery vs JOIN using your example

## 1️⃣ Correlated Subquery Query

```sql
SELECT *
FROM Employees e
WHERE Salary > (
    SELECT AVG(Salary)
    FROM Employees
    WHERE DepartmentId = e.DepartmentId
);
```

**How SQL Executes This**

- For each row in `Employees`:
- Take one employee.
- Run the inner query:

```sql
SELECT AVG(Salary)
FROM Employees
WHERE DepartmentId = e.DepartmentId
```

Compare salary.

If there are 100,000 employees, the inner query may run 100,000 times.

This is called **row-by-row execution**.

**Execution Pattern**

```text
Employee 1 → calculate department avg
Employee 2 → calculate department avg
Employee 3 → calculate department avg
...
Employee N → calculate department avg
```

So the same department average may be computed many times.

## 2️⃣ JOIN / Derived Table Version

```sql
SELECT e.*
FROM Employees e
JOIN (
    SELECT DepartmentId, AVG(Salary) AS AvgSalary
    FROM Employees
    GROUP BY DepartmentId
) d
ON e.DepartmentId = d.DepartmentId
WHERE e.Salary > d.AvgSalary;
```

**How SQL Executes This:**

**First compute department averages once**

```text
DepartmentId | AvgSalary
-------------|----------
1            | 55000
2            | 42500
3            | 70000
```

**Then Join this result with Employees.**

**Execution Pattern**

```text
Step 1 → Calculate averages once
Step 2 → Join Employees with averages
Step 3 → Filter rows
```

# Interview Answer (Short Version)

Correlated subqueries execute the inner query for each row of the outer query, which can cause repeated calculations and poor performance on large datasets.
A JOIN computes the aggregated values once and joins them with the main table, making it more efficient and scalable.

# Multiple CTEs

You can define multiple CTEs.

```sql
WITH DeptAvg AS
(
    SELECT Department, AVG(Salary) AvgSalary
    FROM Employees
    GROUP BY Department
),
HighEarners AS
(
    SELECT *
    FROM Employees
    WHERE Salary > 50000
)
SELECT h.Name, h.Salary, d.AvgSalary
FROM HighEarners h
JOIN DeptAvg d
ON h.Department = d.Department;
```

# CTE with Window Functions

Very common in analytics queries.

**Example: Top salary per department.**

```sql
WITH RankedEmployees AS
(
    SELECT *,
           ROW_NUMBER() OVER
           (
               PARTITION BY Department
               ORDER BY Salary DESC
           ) AS RankNum
    FROM Employees
)
SELECT *
FROM RankedEmployees
WHERE RankNum = 1;
```

# Recursive CTE (Very Important)

Used for hierarchical data.

**Examples:**

- Employee hierarchy
- Folder structure
- Organizational chart
- Bill of materials

**Example: Employee hierarchy**

```sql
WITH EmployeeHierarchy AS
(
    -- Anchor member
    SELECT Id, Name, ManagerId, 0 AS Level
    FROM Employees
    WHERE ManagerId IS NULL

    UNION ALL

    -- Recursive member
    SELECT e.Id, e.Name, e.ManagerId, Level + 1
    FROM Employees e
    JOIN EmployeeHierarchy h
        ON e.ManagerId = h.Id
)
SELECT *
FROM EmployeeHierarchy;
```

# CTE for Deduplication

Common production use case.

```sql
WITH DuplicateRows AS
(
    SELECT *,
           ROW_NUMBER() OVER
           (
               PARTITION BY Name
               ORDER BY Id
           ) AS rn
    FROM Employees
)
DELETE
FROM DuplicateRows
WHERE rn > 1;
```
