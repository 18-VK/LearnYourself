# ASP.NET Core Overview

ASP.NET Core is a modern, open-source, cross-platform web framework used to build web applications, APIs, and microservices using C# and .NET.
It is developed by Microsoft and runs on Windows, Linux, and macOS.

It is the successor of ASP.NET Framework and is designed to be faster, lightweight, and cloud-ready.

## Types of Applications

| Application Type            | Description                                                         |
| --------------------------- | ------------------------------------------------------------------- |
|   REST APIs                 | Backend APIs for mobile apps, web apps, or third-party integrations |
|   Web Applications          | Dynamic websites using MVC                                          |
|   Microservices             | Small independent services in distributed systems                   |
|   Real-time apps            | Chat apps, live dashboards using SignalR                            |
|   Cloud applications        | Apps deployed to cloud platforms                                    |
|   Enterprise applications   | Banking, workflow systems, ERP                                      |

**Example:**

Banking system → APIs built with ASP.NET Core → consumed by web/mobile apps.

## ASP .Net Architecture

ASP.NET Core is a cross-platform, high-performance web framework used to build:

- Web APIs
- MVC Web Applications
- Microservices
- Cloud applications

It is built on a modular middleware pipeline architecture.

**High Level ASP.NET Core Architecture**

```text
  Client (Browser / Mobile App)
        │
        ▼
  Kestrel Web Server
        │
        ▼
  Middleware Pipeline
        │
        ▼
  Routing Middleware
        │
        ▼
  Controller / Endpoint
        │
        ▼
  Business Logic (Services)
        │
        ▼
  Data Access Layer (Repository / EF Core)
        │
        ▼
     Database
        │
        ▼
  Response returned to Client
```

**If interviewer asks:**

> Explain ASP.NET Core architecture

**Answer:**

ASP.NET Core uses a modular middleware pipeline architecture. When a client sends an HTTP request, it is first received by the Kestrel web server. The
request then passes through a series of middleware components such as authentication, authorization, and routing. The routing middleware determines the
appropriate controller and action method. The controller processes the request, interacts with the service and data access layers, and retrieves or updates
data in the database. Finally, the response is returned through the middleware pipeline back to the client.

## ASP .Net Architecture - Components

### 1. Client (Browser / Mobile / Postman)

The client sends an HTTP request to the ASP.NET Core application.

**Example request:**

```http
GET https://api.company.com/api/products/10
```

Client could be:

- Browser
- Mobile App
- React/Angular frontend
- Postman

**Example response expected:**

```json
{
 "id": 10,
 "name": "Laptop",
 "price": 65000
}
```

### 2. Kestrel Web Server

Kestrel is an open-source, cross-platform web server for ASP.NET Core. It is designed to be fast and efficient, making it an ideal choice for modern web
applications. Kestrel can handle HTTP requests and responses, providing a robust foundation for building web applications.
Kestrel is known for its speed and can be used as a standalone server or in combination with a reverse proxy server such as IIS, Nginx, or Apache.

**Why Use Kestrel?**

- **Performance:**
  Kestrel is highly performant and can handle a large number of requests per second.
- **Cross-Platform:**
  Kestrel runs on Windows, macOS, and Linux, making it versatile for different deployment environments.
- **Asynchronous:**
  Built on top of libuv, Kestrel is designed to handle asynchronous I/O operations efficiently.
- **Default Server:**
  It's the default web server in ASP.NET Core, which means it's well-integrated and supported out of the box.

**Responsibilities:**

- Accept HTTP requests
- Process network communication
- Forward requests to ASP.NET Core pipeline

### 3. Middleware

Middleware in ASP.NET Core are software components assembled into an application pipeline to handle HTTP requests and responses. Each component can process
the request, decide to pass it to the next component, or terminate the pipeline.

Middleware is software that acts as an intermediary, connecting different applications, tools, or databases to facilitate data exchange and streamline
communication. Common examples include database middleware (ODBC), message-oriented middleware (RabbitMQ, Kafka), and API gateways.

Each middleware:

- Can modify request
- Pass to next middleware
- Stop pipeline

**Example Pipeline**

```text
Request
   │
   ▼
Exception Middleware
   │
   ▼
Authentication Middleware
   │
   ▼
Authorization Middleware
   │
   ▼
Routing Middleware
   │
   ▼
Controller
```

e.g.:
If request is unauthorized, authentication middleware stops the pipeline.

### 4. Routing

Routing determines which controller and action should handle the request.

**Example request:**

```http
GET /api/products/10
```

Routing decides:

```text
Controller : ProductController
Action     : GetProduct(int id)
```

### 5. Controller

Controllers handle incoming HTTP requests.
Controllers are responsible for routing incoming requests to appropriate actions based on URL patterns.

They:

- Receive request data
- Call business logic
- Return response

### 6. Response Passes Through Middleware

Before reaching client, response passes through middleware again.

**Example:**

```text
Controller Response
      │
      ▼
Authorization Middleware
      │
      ▼
Logging Middleware
      │
      ▼
Response sent to client
```

# Web API vs MVC (focus on Web API)

Both Web API and MVC are frameworks used in ASP.NET Core, but they are designed for different purposes.

- **Web API** → used to build REST APIs
- **MVC** → used to build web applications with UI (views)

ASP.NET Core supports both within the same ecosystem.

## What is ASP.NET Core Web API?

A Web API is used to build RESTful services that return data (usually JSON) instead of HTML pages.

It is mainly used as a backend service for:

- Web applications
- Mobile apps
- Microservices
- Third-party integrations

**Typical architecture:**

```text
Frontend (React / Angular / Mobile)
          ↓
ASP.NET Core Web API
          ↓
Database
```

**Example of ASP.NET Core Web API**

**Controller:**

```csharp
[ApiController]
[Route("api/[controller]")]
public class ProductsController : ControllerBase
{
    [HttpGet]
    public IActionResult GetProducts()
    {
        var products = new List<string>
        {
            "Laptop",
            "Mouse",
            "Keyboard"
        };

        return Ok(products);
    }
}
```

**API Request:**

```http
GET /api/products
```

**Response:**

```json
[
 "Laptop",
 "Mouse",
 "Keyboard"
]
```

Notice:

- Returns JSON
- No UI rendering
- Consumed by another application

## What is ASP.NET Core MVC?

MVC stands for:

- Model
- View
- Controller

It is used to build server-rendered web applications.

**Flow:**

```text
Browser
  ↓
Controller
  ↓
Model
  ↓
View (HTML page)
  ↓
Browser
```

**Example of ASP.NET Core MVC**

**Controller:**

```csharp
public class ProductsController : Controller
{
    public IActionResult Index()
    {
        var products = new List<string>
        {
            "Laptop",
            "Mouse",
            "Keyboard"
        };

        return View(products);
    }
}
```

**View (Razor):**

```html
<h2>Products</h2>
<ul>
@foreach (var product in Model)
{
    <li>@product</li>
}
</ul>
```

**Request:**

```http
GET /products
```

**Response:**

```html
<h2>Products</h2>
<ul>
<li>Laptop</li>
<li>Mouse</li>
<li>Keyboard</li>
</ul>
```

MVC returns HTML UI pages.

## Key Differences

| Feature               | Web API               | MVC          |
| --------------------- | --------------------- | ------------ |
| Purpose               | Build APIs            | Build web UI |
| Response type         | JSON / XML            | HTML views   |
| Used by               | Mobile, SPA, services | Browsers     |
| Controller base class | `ControllerBase`      | `Controller` |
| View support          | No                    | Yes          |
| Typical architecture  | Backend service       | Full web app |

## When to Use Web API

Use Web API when:

- Building backend services
- Developing mobile app backend
- Creating microservices
- Exposing APIs for third parties
- Building SPA applications

**Example:**

```text
Angular frontend
↓
ASP.NET Core Web API
↓
SQL Server
```

## When to Use MVC

Use MVC when:

- Building traditional web applications
- Server renders HTML pages
- No separate frontend framework

**Example:**

```text
Browser
↓
ASP.NET MVC
↓
Razor Views
```

## Why Web API is More Popular Today

Modern systems use separate frontend and backend.

**Example architecture:**

```text
Frontend (React / Angular)
        ↓
REST API (ASP.NET Core Web API)
        ↓
Database
```

**Advantages:**

- Supports mobile apps
- Supports microservices
- Independent frontend/backend
- Scalable architecture

# Minimal API 

Minimal APIs are best for lightweight microservices or prototypes.

Use Case Scenarios : 

- A weather notification service with 3 endpoints (forecast, preferences, alerts).
- Internal microservice for product catalog.
- Proof-of-concept apps where speed matters more than structure.
