# Recommended folder structure : Web API

```text
MyApi/
│
├── Controllers/
│   └── ProductsController.cs
│
├── Models/
│   └── Product.cs
│
├── DTOs/
│   ├── CreateProductDto.cs
│   └── UpdateProductDto.cs
│
├── Validators/
│   ├── CreateProductDtoValidator.cs
│   └── UpdateProductDtoValidator.cs
│
├── Services/
│   ├── IProductService.cs
│   └── ProductService.cs
│
├── Repositories/
│   ├── IProductRepository.cs
│   └── ProductRepository.cs
│
├── Middleware/
│   └── ExceptionHandlingMiddleware.cs
│
├── Program.cs
└── appsettings.json
```

## What each folder means

- **Controllers:** HTTP endpoints only.
- **Models:** domain/entity classes.
- **DTOs:** request/response contracts.
- **Validators:** validation rules for DTOs.
- **Services:** business logic.
- **Repositories:** data access.
- **Middleware:** cross-cutting concerns like exceptions/logging.

# Standard controller-based Web API setup

Controllers use routing middleware to match incoming URLs to actions, and dependency injection is built into ASP.NET Core so controllers can request services through constructors.

## Program.cs

```csharp
var builder = WebApplication.CreateBuilder(args);

builder.Services.AddControllers();
builder.Services.AddEndpointsApiExplorer();
builder.Services.AddSwaggerGen();

var app = builder.Build();

if (app.Environment.IsDevelopment())
{
    app.UseSwagger();
    app.UseSwaggerUI();
}

app.UseHttpsRedirection();
app.MapControllers();
app.Run();
```

> **Note:** some things here can be modified as per requirement.

## Sample files

**Model**

```csharp
namespace MyApi.Models;

public class Product
{
    public int Id { get; set; }
    public string Name { get; set; } = string.Empty;
    public decimal Price { get; set; }
}
```

**DTOs**

```csharp
using System.ComponentModel.DataAnnotations;

namespace MyApi.DTOs;

public class CreateProductDto
{
    [Required]
    public string Name { get; set; } = string.Empty;

    [Range(1, 100000)]
    public decimal Price { get; set; }
}
```

```csharp
using System.ComponentModel.DataAnnotations;

namespace MyApi.DTOs;

public class UpdateProductDto
{
    [Required]
    public string Name { get; set; } = string.Empty;

    [Range(1, 100000)]
    public decimal Price { get; set; }
}
```

**Validator**

```csharp
using FluentValidation;
using MyApi.DTOs;

namespace MyApi.Validators;

public class CreateProductDtoValidator : AbstractValidator<CreateProductDto>
{
    public CreateProductDtoValidator()
    {
        RuleFor(x => x.Name)
            .NotEmpty()
            .MinimumLength(3)
            .MaximumLength(100);

        RuleFor(x => x.Price)
            .GreaterThan(0);
    }
}
```

**Controller**

```csharp
using Microsoft.AspNetCore.Mvc;
using MyApi.DTOs;
using MyApi.Models;

namespace MyApi.Controllers;

[ApiController]
[Route("api/products")]
public class ProductsController : ControllerBase
{
    [HttpGet]
    public IActionResult GetAll()
    {
        var data = new[]
        {
            new Product { Id = 1, Name = "Pen", Price = 10 },
            new Product { Id = 2, Name = "Notebook", Price = 50 }
        };

        return Ok(data);
    }

    [HttpGet("{id:int}")]
    public IActionResult GetById(int id)
    {
        return Ok(new Product { Id = id, Name = "Pen", Price = 10 });
    }

    [HttpPost]
    public IActionResult Create(CreateProductDto dto)
    {
        return Ok(dto);
    }
}
```

With `[ApiController]`, model validation errors automatically return HTTP 400, and attribute routing is required. The default 400 body is
`ValidationProblemDetails`.

# Controller API + FluentValidation, manual validation

FluentValidation's official docs recommend manual validation as the most straightforward approach, and they note that automatic validation through ASP.NET's
validation pipeline is no longer recommended for new projects; they recommend manual validation or using a filter-based approach instead.

**Example: Program.cs**

```csharp
using FluentValidation;
using MyApi.Services;

var builder = WebApplication.CreateBuilder(args);

builder.Services.AddControllers();
builder.Services.AddEndpointsApiExplorer();
builder.Services.AddSwaggerGen();

builder.Services.AddScoped<IProductService, ProductService>();
builder.Services.AddValidatorsFromAssemblyContaining<Program>();

var app = builder.Build();

app.UseHttpsRedirection();
app.MapControllers();
app.Run();
```

**Controller example:**

```csharp
using FluentValidation;
using Microsoft.AspNetCore.Mvc;
using MyApi.DTOs;

[ApiController]
[Route("api/products")]
public class ProductsController : ControllerBase
{
    [HttpPost]
    public async Task<IActionResult> Create(
        CreateProductDto dto,
        [FromServices] IValidator<CreateProductDto> validator)
    {
        var result = await validator.ValidateAsync(dto);

        if (!result.IsValid)
            return BadRequest(result.Errors);

        return Ok(dto);
    }
}
```

**Use when:** you want explicit validation and easy debugging.

# Best default template to start with

```csharp
using FluentValidation;
using MyApi.Filters;
using MyApi.Repositories;
using MyApi.Services;

var builder = WebApplication.CreateBuilder(args);

builder.Services.AddControllers(options =>
{
    options.Filters.Add<ValidationFilter>(); // needed only for filter-based validation 
});
builder.Services.AddEndpointsApiExplorer();
builder.Services.AddSwaggerGen();

builder.Services.AddScoped<ValidationFilter>();
builder.Services.AddScoped<IProductService, ProductService>();
builder.Services.AddScoped<IProductRepository, ProductRepository>();
builder.Services.AddValidatorsFromAssemblyContaining<Program>();

var app = builder.Build();

if (app.Environment.IsDevelopment())
{
    app.UseSwagger();
    app.UseSwaggerUI();
}

app.UseHttpsRedirection();
app.MapControllers();
app.Run();
```
