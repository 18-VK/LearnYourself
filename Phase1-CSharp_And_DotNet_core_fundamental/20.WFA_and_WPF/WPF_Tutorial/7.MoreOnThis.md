# What is ObservableCollection&lt;T&gt;?

A collection that notifies the UI when items are added, removed, or the whole list changes.

It implements:

- `IEnumerable`
- `ICollection`
- `INotifyCollectionChanged`
- `INotifyPropertyChanged`

## Why List&lt;T&gt; is NOT enough ❌

Using `List<T>`:

```csharp
public List<Transaction> Transactions { get; } = new();
```

**UI behavior:**

```csharp
Transactions.Add(new Transaction());
```

- ❌ UI does NOT update
- ❌ DataGrid doesn't refresh

Because:

`List<T>` does not notify the UI.

## Why ObservableCollection&lt;T&gt; works ✅

```csharp
public ObservableCollection<Transaction> Transactions { get; }
```

When you call:

```csharp
Transactions.Add(item);
Transactions.Remove(item);
Transactions.Clear();
```

- ✔ WPF gets notified
- ✔ UI updates automatically
- ✔ No manual refresh needed

✔ **It notifies when:**

| Action  | UI updates? |
| ------- | ----------- |
| Add     | ✅           |
| Remove  | ✅           |
| Clear   | ✅           |
| Replace | ✅           |

### ❌ It does NOT notify when:

```csharp
Transactions[0].Amount = 500;
```

**Why?**

- Collection didn't change
- Item changed

**Fix:** Items must implement `INotifyPropertyChanged`

```csharp
public class Transaction : INotifyPropertyChanged
{
    private decimal _amount;
    public decimal Amount
    {
        get => _amount;
        set
        {
            _amount = value;
            OnPropertyChanged();
        }
    }

    public event PropertyChangedEventHandler PropertyChanged;
    protected void OnPropertyChanged([CallerMemberName] string name = null)
        => PropertyChanged?.Invoke(this, new PropertyChangedEventArgs(name));
}
```

- ✔ UI updates when a property changes
- ✔ Required for editable DataGrid

### Replace entire collection (IMPORTANT)

❌ **Wrong**

```csharp
Transactions = new ObservableCollection<Transaction>(newList);
```

(UI won't update unless property raises change)

✅ **Correct**

```csharp
Transactions.Clear();
foreach (var item in newList)
    Transactions.Add(item);
```

or

```csharp
private ObservableCollection<Transaction> _transactions;
public ObservableCollection<Transaction> Transactions
{
    get => _transactions;
    set
    {
        _transactions = value;
        OnPropertyChanged();
    }
}
```

### Threading rule (VERY IMPORTANT)

`ObservableCollection` must be modified on the UI thread.

# Validations

## 1️⃣ What is WPF Validation?

Validation ensures bound data is correct before updating the source.

**Typical examples:**

- Required field
- Numeric range
- Email format
- Business rules (Amount > 0)

WPF supports multiple validation layers.

## 2️⃣ Validation approaches (most → least used)

| Approach               | Where logic lives | MVVM friendly |
| ---------------------- | ----------------- | ------------- |
| `INotifyDataErrorInfo` | ViewModel         | ⭐⭐⭐⭐⭐         |
| `IDataErrorInfo`       | Model/ViewModel   | ⭐⭐⭐⭐          |
| `ValidationRules`      | XAML              | ⭐⭐            |
| Exceptions             | Model             | ⭐             |

> **Note:** will only go through `INotifyDataErrorInfo`.

## 3️⃣ Best practice (Modern MVVM) — INotifyDataErrorInfo

- ✔ Supports async validation
- ✔ Multiple errors per property
- ✔ No UI logic in View

**`INotifyDataErrorInfo` interface:**

```csharp
public interface INotifyDataErrorInfo
{
    bool HasErrors { get; }
    event EventHandler<DataErrorsChangedEventArgs> ErrorsChanged;
    IEnumerable GetErrors(string propertyName);
}
```

## Example: Amount validation (> 0)

**ViewModel**

```csharp
using System.Collections;
using System.Collections.Generic;
using System.ComponentModel;

public class TransactionViewModel : INotifyPropertyChanged, INotifyDataErrorInfo
{
    private readonly Dictionary<string, List<string>> _errors = new();

    private decimal _amount;
    public decimal Amount
    {
        get => _amount;
        set
        {
            _amount = value;
            OnPropertyChanged();
            ValidateAmount();
        }
    }

    private void ValidateAmount()
    {
        ClearErrors(nameof(Amount));

        if (Amount <= 0)
            AddError(nameof(Amount), "Amount must be greater than zero.");
    }

    public bool HasErrors => _errors.Count > 0;

    public event EventHandler<DataErrorsChangedEventArgs> ErrorsChanged;

    public IEnumerable GetErrors(string propertyName)
        => _errors.ContainsKey(propertyName) ? _errors[propertyName] : null;

    private void AddError(string propertyName, string error)
    {
        if (!_errors.ContainsKey(propertyName))
            _errors[propertyName] = new List<string>();

        _errors[propertyName].Add(error);
        ErrorsChanged?.Invoke(this, new DataErrorsChangedEventArgs(propertyName));
    }

    private void ClearErrors(string propertyName)
    {
        if (_errors.Remove(propertyName))
            ErrorsChanged?.Invoke(this, new DataErrorsChangedEventArgs(propertyName));
    }

    // INotifyPropertyChanged
    public event PropertyChangedEventHandler PropertyChanged;
    protected void OnPropertyChanged(string name = null)
        => PropertyChanged?.Invoke(this, new PropertyChangedEventArgs(name));
}
```

- Have functions to add error, clear error, and get error for fields
- Have dictionary collecting errors

## Why is this event required?

```csharp
public event EventHandler<DataErrorsChangedEventArgs> ErrorsChanged;
```

This event is required by `INotifyDataErrorInfo`.

It tells WPF "validation errors for this property have changed — re-query them now."

Without it, WPF will never know that errors were added or removed.

WPF does not continuously poll your ViewModel for errors.
Instead, it works like this:

- User changes a value
- ViewModel validates and updates its error collection
- ViewModel raises `ErrorsChanged`
- WPF calls `GetErrors(propertyName)`
- UI updates (red border, tooltip, summary, button state)

No event → no UI update.

**XAML**

```xml
<TextBox Text="{Binding Amount,
                UpdateSourceTrigger=PropertyChanged,
                ValidatesOnNotifyDataErrors=True}" />
```

- ✔ Red border automatically
- ✔ Tooltip shows error
- ✔ No code-behind

> **Note:** this is the best approach in modern WPF.
