# Why use Stored Procedure instead of inline query?

✅ **Interview-Ready Answer**

## 🔹 Definition (start strong)

👉 Stored Procedures are preferred over inline queries because they provide better performance, security, and maintainability.

## 🔹 Key Advantages

### 🔸 1. Performance (VERY IMPORTANT)

- Stored procedures are precompiled and cached
- Reduce query parsing and compilation time

👉 Faster execution compared to repeated inline queries

### 🔸 2. Security

- Prevent SQL Injection (when using parameters)
- Can restrict direct table access
- Users can execute procedure without accessing tables

### 🔸 3. Reusability

- Write once, use multiple times
- Centralized logic in DB

### 🔸 4. Maintainability

- Changes can be done in DB without modifying application code
- Easier to manage complex logic

# The N+1 Problem

## Definition (start strong)

👉 The N+1 problem occurs when an application executes one query to fetch data and then N additional queries to fetch related data, leading to performance issues.

## 🔹 How it Happens (Explain clearly)

👉 **Example:**

- One query to get all users
- Then for each user → one query to get orders

👉 **Total queries:**

```text
1 (users) + N (orders per user) = N+1 queries
```

## Example (Entity Framework)

```csharp
var users = context.Users.ToList();

foreach (var user in users)
{
    var orders = context.Orders
        .Where(o => o.UserId == user.Id)
        .ToList();
}
```

## How to Fix (VERY IMPORTANT)

### 🔸 1. Eager Loading (Best Solution)

```csharp
var users = context.Users
    .Include(u => u.Orders)
    .ToList();
```

👉 Loads all data in single query

### 🔸 2. Projection

```csharp
var users = context.Users
    .Select(u => new {
        u.Name,
        Orders = u.Orders
    })
    .ToList();
```

### 🔸 3. Explicit Loading (Controlled)

```csharp
context.Entry(user)
    .Collection(u => u.Orders)
    .Load();
```

## SQL

**Correct Approach (Optimized Query)**

✅ **Use JOIN (Best Solution)**

```sql
SELECT u.Id, u.Name, o.OrderId
FROM Users u
LEFT JOIN Orders o ON u.Id = o.UserId;
```

👉 Fetches everything in single query

🔹 **Alternative Approach**

✅ **Use IN clause**

```sql
SELECT * FROM Orders
WHERE UserId IN (SELECT Id FROM Users);
```
