# Quick overview (the 6 common join types)

- **INNER JOIN:**
  return rows that match on both sides.
- **LEFT (LEFT OUTER) JOIN:**
  return all rows from left table and matching rows from right (NULL when no match).
- **RIGHT (RIGHT OUTER) JOIN:**
  all rows from right table and matches from left (rarely used).
- **FULL OUTER JOIN:**
  rows that match plus unmatched rows from either side (NULLs where missing).
- **CROSS JOIN:**
  Cartesian product (every left × every right).
- **APPLY (CROSS APPLY / OUTER APPLY):**
  SQL Server: apply a table-valued expression per row (very handy for "top N per group").

# Explained with Example

## INNER JOIN (most common)

**Definition:** Return rows where join condition matches on both tables.

**Example: Inner join on customer id column**

```sql
SELECT c.CustomerId, c.Name, o.OrderId, o.Amount
FROM Customers c
INNER JOIN Orders o
  ON c.CustomerId = o.CustomerId;
```

**Result rows (exact):**

| CustomerId | Name  | OrderId | Amount |
| ---------- | ----- | ------- | ------ |
| 1          | Alice | 101     | 100.00 |
| 1          | Alice | 102     | 50.00  |
| 2          | Bob   | 103     | 75.00  |

**Use-case:** Get all orders with customer info. Use when you only want matched pairs.

## LEFT (LEFT OUTER) JOIN

**Definition:** All rows from left table; matching rows from right or NULL when none.

**Example: All Customers with order info (if exist else NULL)**

```sql
SELECT c.CustomerId, c.Name, o.OrderId, o.Amount
FROM Customers c
LEFT JOIN Orders o
  ON c.CustomerId = o.CustomerId;
```

**Result:**

| CustomerId | Name  | OrderId | Amount |
| ---------- | ----- | ------- | ------ |
| 1          | Alice | 101     | 100.00 |
| 1          | Alice | 102     | 50.00  |
| 2          | Bob   | 103     | 75.00  |
| 3          | Carol | NULL    | NULL   |

**Use-case:** Find all customers and their orders (including customers with no orders).

## RIGHT JOIN

**Definition:** All rows from right table and matches from left (rarely used).
Same idea as LEFT but keeping the right table rows.

**Example:**

```sql
SELECT c.CustomerId, c.Name, o.OrderId, o.Amount
FROM Customers c
RIGHT JOIN Orders o
  ON c.CustomerId = o.CustomerId;
```

**Result:**

| CustomerId | Name  | OrderId | Amount |
| ---------- | ----- | ------- | ------ |
| 1          | Alice | 101     | 100.00 |
| 1          | Alice | 102     | 50.00  |
| 2          | Bob   | 103     | 75.00  |
| NULL       | NULL  | 104     | 60.00  |

> **Note:** RIGHT JOIN is functionally identical to swapping table positions and using LEFT JOIN; many teams prefer LEFT JOIN for
> clarity.

## FULL OUTER JOIN

**Definition:** Return matches and unmatched rows from both sides.

**Example:**

```sql
SELECT c.CustomerId, c.Name, o.OrderId, o.Amount
FROM Customers c
FULL OUTER JOIN Orders o
  ON c.CustomerId = o.CustomerId;
```

**Result:**

| CustomerId | Name  | OrderId | Amount |
| ---------- | ----- | ------- | ------ |
| 1          | Alice | 101     | 100.00 |
| 1          | Alice | 102     | 50.00  |
| 2          | Bob   | 103     | 75.00  |
| 3          | Carol | NULL    | NULL   |
| NULL       | NULL  | 104     | 60.00  |

**Use-case:** Data reconciliation between two sources; identify rows present only on one side.

## CROSS JOIN (Cartesian product)

**Definition:** Every left row × every right row.

If Customers = 3 rows and Orders = 4 rows → result = 12 rows.

**Example:**

```sql
SELECT c.Name, o.OrderId
FROM Customers c
CROSS JOIN Orders o;
```

**Result:**

| CustomerId | Name  | OrderId | Amount |
| ---------- | ----- | ------- | ------ |
| 1          | Alice | 101     | 100.00 |
| 1          | Alice | 102     | 50.00  |
| 1          | Alice | 103     | 75.00  |
| 1          | Alice | 104     | 60.00  |
| 2          | Bob   | 101     | 100.00 |
| 2          | Bob   | 102     | 50.00  |
| 2          | Bob   | 103     | 75.00  |
| 2          | Bob   | 104     | 60.00  |
| 3          | Carol | 101     | 100.00 |
| 3          | Carol | 102     | 50.00  |
| 3          | Carol | 103     | 75.00  |
| 3          | Carol | 104     | 60.00  |

**Use-case:** Generating combinations, test data, grid expansions. Beware: produces explosive row counts.

## SELF JOIN (join a table to itself)

**Example:**

```sql
CREATE TABLE Employees (EmpId INT, Name NVARCHAR(50), ManagerId INT);
INSERT INTO Employees VALUES (1,'John',NULL),(2,'Sarah',1),(3,'Mike',1),(4,'Anna',2);

SELECT e.Name AS Employee, m.Name AS Manager
FROM Employees e
LEFT JOIN Employees m
  ON e.ManagerId = m.EmpId;
```

**Result:** list of emps with manager name

| Employee | Manager |
| -------: | ------: |
|     John |    NULL |
|    Sarah |    John |
|     Mike |    John |
|     Anna |   Sarah |

**Use-case:** Hierarchies, org charts.

## APPLY (SQL Server-specific)

- `CROSS APPLY` acts like a correlated subquery that must return rows (like inner join).
- `OUTER APPLY` keeps rows from left even if right returns nothing (like left join).

### OUTER APPLY

Get latest order (top 1) per customer:

```sql
SELECT c.CustomerId, c.Name, lo.OrderId, lo.Amount
FROM Customers c
OUTER APPLY (
  SELECT TOP(1) o.OrderId, o.Amount
  FROM Orders o
  WHERE o.CustomerId = c.CustomerId
  ORDER BY o.OrderId DESC
) lo;
```

**Use-case:** "Top N per group", invoking table-valued functions per row.

**Result:**

| CustomerId | Name  | OrderId | Amount |
| ---------- | ----- | ------- | ------ |
| 1          | Alice | 102     | 50.00  |
| 2          | Bob   | 103     | 75.00  |
| 3          | Carol | NULL    | NULL   |

Most recent order per customer.

### CROSS APPLY

`CROSS APPLY` works like `INNER JOIN`.
If the subquery returns no rows → that customer is removed.

**Example:**

```sql
SELECT c.CustomerId, c.Name, lo.OrderId, lo.Amount
FROM Customers c
CROSS APPLY (
  SELECT TOP(1) o.OrderId, o.Amount
  FROM Orders o
  WHERE o.CustomerId = c.CustomerId
  ORDER BY o.OrderId DESC
) lo;
```

**Result:**

| CustomerId | Name  | OrderId | Amount |
| ---------- | ----- | ------- | ------ |
| 1          | Alice | 102     | 50.00  |
| 2          | Bob   | 103     | 75.00  |

## Anti-join (find unmatched rows)

Find customers with no orders.

**LEFT JOIN + IS NULL (classic):**

```sql
SELECT c.CustomerId, c.Name
FROM Customers c
LEFT JOIN Orders o ON c.CustomerId = o.CustomerId
WHERE o.OrderId IS NULL;
```

**Prefer NOT EXISTS (often more efficient & safer with duplicates):**

```sql
SELECT c.CustomerId, c.Name
FROM Customers c
WHERE NOT EXISTS (
  SELECT 1 FROM Orders o WHERE o.CustomerId = c.CustomerId
);
```

**Result:** Carol (CustomerId 3).

**Use-case:** Orphan detection, cleanup tasks.

## Semi-join (existence check) vs INNER JOIN

If you only want customers who have orders, use `EXISTS` (semi-join) — it avoids duplicate customers if there are multiple
orders.

**Bad (might duplicate customers):**

```sql
SELECT c.CustomerId, c.Name
FROM Customers c
INNER JOIN Orders o ON c.CustomerId = o.CustomerId;
-- This returns one row per order (duplicates)
```

**Good:**

```sql
SELECT DISTINCT c.CustomerId, c.Name
FROM Customers c
INNER JOIN Orders o ON c.CustomerId = o.CustomerId;
```

**Better:**

```sql
SELECT c.CustomerId, c.Name
FROM Customers c
WHERE EXISTS (SELECT 1 FROM Orders o WHERE o.CustomerId = c.CustomerId);
```

# INNER vs OUTER Join

- `INNER JOIN` returns only matching rows from both tables.
- `OUTER JOIN` returns matching rows plus unmatched rows from one or both tables, filling missing columns with NULL.

# The LEFT JOIN + WHERE Mistake

Many developers accidentally turn a LEFT JOIN into an INNER JOIN by placing conditions in the WHERE clause.

## ✅ Correct LEFT JOIN

```sql
SELECT c.Name, o.OrderId
FROM Customers c
LEFT JOIN Orders o
ON c.CustomerId = o.CustomerId;
```

**Result:**

| Name  | OrderId |
| ----- | ------- |
| Alice | 101     |
| Alice | 102     |
| Bob   | 103     |
| Carol | NULL    |

## ❌ The Mistake

Now someone writes:

```sql
SELECT c.Name, o.OrderId
FROM Customers c
LEFT JOIN Orders o
ON c.CustomerId = o.CustomerId
WHERE o.Amount > 60;
```

🔎 **What Happens?**

The `WHERE` clause runs after the join.

For Carol:

```text
OrderId = NULL
Amount = NULL
```

Condition:

```text
NULL > 60
```

Result = UNKNOWN → filtered out ❌

**Result:**

| Name  | OrderId |
| ----- | ------- |
| Alice | 101     |
| Bob   | 103     |

Carol disappeared ❌
Your LEFT JOIN became INNER JOIN.

## Why This Happens (Logical Order)

SQL execution order:

- FROM
- JOIN
- WHERE
- GROUP BY
- SELECT
- ORDER BY

So:

- `LEFT JOIN` creates NULL rows
- `WHERE` removes them

## ✅ Correct Way (Condition in ON)

Move condition inside JOIN:

```sql
SELECT c.Name, o.OrderId
FROM Customers c
LEFT JOIN Orders o
ON c.CustomerId = o.CustomerId
   AND o.Amount > 60;
```

## Real Interview Question

Interviewer may ask:

> Why is my LEFT JOIN not returning unmatched rows?

**Correct answer:**

Because a `WHERE` condition on the right table filtered out NULL values, effectively converting the LEFT JOIN into an INNER
JOIN.

# Joining multiple tables

**Example:**

```sql
-- Show students and the courses they enrolled in 

SELECT S.StudentId, S.StudentName, CRS.CourseID, CRS.CourseName, EN.EnrollmentId 
FROM Student S INNER JOIN Enrollments EN ON S.StudentId = EN.StudentId 
INNER JOIN Courses CRS ON EN.CourseId = CRS.CourseID;
```

# Group By on multiple columns

```sql
-- Show students with number of courses enrolled.

SELECT ST.StudentId, ST.StudentName, COUNT(EN.CourseId) AS CoursesCount 
FROM Student ST INNER JOIN Enrollments EN ON ST.StudentId = EN.StudentId 
GROUP BY ST.StudentId, ST.StudentName;
```

# Find instructors who teach more than one course

**Example:**

```sql
Select INST.InstructorId,INST.InstructorName, STRING_AGG(CT.CourseName, ', ') AS CoursesTaught
from Instructors INST Inner join Courses CT
on INST.InstructorId = CT.InstructorId
group by INST.InstructorId, INST.InstructorName
having COUNT(INST.InstructorId) > 1;
```
