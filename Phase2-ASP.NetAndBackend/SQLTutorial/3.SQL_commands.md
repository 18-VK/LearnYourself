# SQL Basics commands

## CREATE DATABASE

- Used to create a new database

```sql
CREATE DATABASE CompanyDB;
```

Now use it:

```sql
USE CompanyDB;
```

✅ Creates a new database named `CompanyDB`

## CREATE TABLE

- Used to create a table inside a database

```sql
CREATE TABLE Employees (
    Id INT PRIMARY KEY,
    Name NVARCHAR(100),
    Age INT,
    Salary DECIMAL(10,2),
    IsActive BIT,
    CreatedAt DATETIME2 DEFAULT GETDATE()
);
```

## INSERT

- Used to insert new records

**Insert single row:**

```sql
INSERT INTO Employees (Id, Name, Age, Salary, IsActive)
VALUES (1, 'Aman Kumar', 28, 50000.00, 1);
```

**Insert multiple rows:**

```sql
INSERT INTO Employees (Id, Name, Age, Salary, IsActive)
VALUES 
(2, 'Rahul', 30, 60000.00, 1),
(3, 'Priya', 26, 45000.00, 0);
```

## SELECT *

- Used to retrieve data

```sql
SELECT * FROM Employees;
```

Returns all columns and rows.

Better practice (avoid `*` in production):

```sql
SELECT Name, Salary FROM Employees;
```

## UPDATE

- Used to modify existing data

Syntax : 
```sql 
UPDATE table_name
SET column1 = value1,
    column2 = value2,
    column3 = value3
WHERE condition;   

```

```sql
UPDATE Employees
SET Salary = 55000
WHERE Id = 1;
```

> ⚠ Always use `WHERE` clause!

❌ **Without WHERE:**

```sql
UPDATE Employees
SET Salary = 10000;
```

This updates ALL rows.

### Update Using CASE (Different Values for Different Rows)

Example: Give different salary increments.

```sql
UPDATE Employees
SET Salary = CASE 
                WHEN Department = 'IT' THEN Salary + 5000
                WHEN Department = 'HR' THEN Salary + 3000
             END;
```

> ⚠ Important: If there is no `ELSE`, then rows that do not match any `WHEN` condition get `NULL`.

Example:

```sql
UPDATE Employees
SET Salary = CASE
                WHEN Department = 'IT' THEN Salary + 5000
                WHEN Department = 'HR' THEN Salary + 3000
                ELSE Salary
             END;
```

✅ With `ELSE Salary`, all other departments keep their original salary.

✅ Without `ELSE`, unmatched departments become `NULL`.

### Best Practice

Use `ELSE` whenever you want a default value, for example:

```sql
ELSE Salary
```

or

```sql
ELSE 0
```

This avoids accidental `NULL` updates.

### Example with default bonus

```sql
UPDATE Employees
SET Salary = CASE
                WHEN Department = 'IT' THEN Salary + 5000
                WHEN Department = 'HR' THEN Salary + 3000
                ELSE Salary + 500
             END;
```

✅ Meaning:

- `IT` employees get +5000
- `HR` employees get +3000
- all other departments get +500

This is useful when you want a default increment for all remaining departments instead of leaving them as `NULL`.

## DELETE

- Used to remove specific rows

```sql
DELETE FROM Employees
WHERE Id = 3;
```

Removes only that row.

❌ **Without WHERE:**

```sql
DELETE FROM Employees;
```

Deletes all rows (but table remains).

## TRUNCATE

- Removes ALL rows quickly

```sql
TRUNCATE TABLE Employees;
```

## DROP

- Completely removes object

**Drop table:**

```sql
DROP TABLE Employees;
```

**Drop database:**

```sql
DROP DATABASE CompanyDB;
```

> ⚠ This permanently removes structure + data

| Feature                          | DELETE          | TRUNCATE                    | DROP                          |
| -------------------------------- | --------------- | --------------------------- | ----------------------------- |
| Removes Data                     | ✅ Selected rows | ✅ All rows                  | ✅ All data                    |
| Removes Table Structure          | ❌ No            | ❌ No                        | ✅ Yes                         |
| WHERE clause allowed             | ✅ Yes           | ❌ No                        | ❌ No                          |
| Logging                          | Row-by-row      | Minimal logging             | Minimal logging               |
| Speed                            | Slower          | Faster                      | Fast                          |
| Identity Reset                   | ❌ No            | ✅ Yes                       | N/A (table removed)           |
| Triggers Fire                    | ✅ Yes           | ❌ No                        | ❌ No                          |
| Foreign Key Restriction          | Allowed         | ❌ Not allowed if referenced | ❌ Not allowed if referenced   |
| Can Be Rolled Back (Transaction) | ✅ Yes           | ✅ Yes                       | ✅ Yes (if inside transaction) |
| Requires Table Lock              | Row/Page Lock   | Table Lock                  | Table Lock                    |

✅ **Does Each Command Reset Identity?**

| Command  | Resets Identity?                 |
| -------- | -------------------------------- |
| DELETE   | ❌ No                             |
| TRUNCATE | ✅ Yes                            |
| DROP     | ✅ Yes (because table is removed) |

# Filtering Data

## WHERE

- Used to filter rows based on condition.

```sql
SELECT *
FROM Employees
WHERE Salary > 50000;
```

👉 Returns only employees with salary greater than 50,000.

## Comparison Operators

| Operator | Meaning          |
| -------- | ---------------- |
| =        | Equal            |
| <> or != | Not equal        |
| >        | Greater than     |
| <        | Less than        |
| >=       | Greater or equal |
| <=       | Less or equal    |

**Example:**

```sql
SELECT * 
FROM Employees
WHERE Age >= 30;
```

## AND / OR / NOT

- Combine multiple conditions.

**Using AND:**

```sql
SELECT *
FROM Employees
WHERE Salary > 50000 AND IsActive = 1;
```

**Using OR:**

```sql
SELECT *
FROM Employees
WHERE Age < 25 OR Salary > 70000;
```

**Using NOT:**

```sql
SELECT *
FROM Employees
WHERE NOT IsActive = 1;
```

## BETWEEN

- Used for range filtering (inclusive).

```sql
SELECT *
FROM Employees
WHERE Salary BETWEEN 40000 AND 80000;
```

Equivalent to:

```sql
WHERE Salary >= 40000 AND Salary <= 80000;
```

## IN

- Match multiple specific values.

```sql
SELECT *
FROM Employees
WHERE Department IN ('HR', 'IT', 'Finance');
```

## LIKE (Pattern Matching)

- Used for text search.

| Pattern | Meaning                  |
| ------- | ------------------------ |
| %       | Any number of characters |
| _       | Single character         |

**Examples:**

```sql
-- Starts with A
SELECT *
FROM Employees
WHERE Name LIKE 'A%';

-- Ends with n
SELECT *
FROM Employees
WHERE Name LIKE '%n';

-- Contains 'man'
SELECT *
FROM Employees
WHERE Name LIKE '%man%';
```

## IS NULL / IS NOT NULL

```sql
SELECT *
FROM Employees
WHERE MiddleName IS NULL;

SELECT *
FROM Employees
WHERE MiddleName IS NOT NULL;
```

## TOP (Limit Rows)

- Used to return limited rows.

```sql
SELECT TOP 5 *
FROM Employees;
```

With percentage:

```sql
SELECT TOP 10 PERCENT *
FROM Employees;
```

# Sorting Data

## ORDER BY

- Used to sort results.

**Ascending (default):**

```sql
SELECT *
FROM Employees
ORDER BY Salary;
```

**Descending:**

```sql
SELECT *
FROM Employees
ORDER BY Salary DESC;
```

## Multiple Column Sorting

```sql
SELECT *
FROM Employees
ORDER BY Department ASC, Salary DESC;
```

👉 First sorts by Department

👉 Within department, sorts by Salary descending

## ORDER BY with Alias

```sql
SELECT Name, Salary * 12 AS AnnualSalary
FROM Employees
ORDER BY AnnualSalary DESC;
```

## OFFSET

- `OFFSET` is used with `ORDER BY` to skip a specified number of rows before returning the remaining rows.
- It is mainly used for pagination (like showing page 2, page 3 in UI grids).

**Basic Syntax:**

```sql
SELECT column1, column2
FROM table_name
ORDER BY column_name
OFFSET number_of_rows ROWS;
```

👉 `ORDER BY` is mandatory when using `OFFSET`.

## OFFSET + FETCH (Pagination)

- `OFFSET` → How many rows to skip
- `FETCH NEXT` → How many rows to return

**Example 1: Skip First 5 Rows**

```sql
SELECT *
FROM Employees
ORDER BY Id
OFFSET 5 ROWS;
```

- ✔ Skips first 5 records
- ✔ Returns remaining records

**Example 2: Pagination (Page 2, 5 records per page)**

```sql
SELECT *
FROM Employees
ORDER BY Id
OFFSET 5 ROWS
FETCH NEXT 5 ROWS ONLY;
```

- ✔ Skips first 5 rows
- ✔ Returns next 5 rows

🔹 **Important Rules**

| Rule                | Explanation                            |
| ------------------- | -------------------------------------- |
| `ORDER BY` required | OFFSET cannot be used without ORDER BY |
| Introduced in       | SQL Server 2012                        |
| Works with          | SELECT statement only                  |
| Cannot be used in   | DELETE/UPDATE directly                 |

## OFFSET vs TOP

**Using TOP:**

```sql
SELECT TOP 5 *
FROM Employees
ORDER BY Id;
```

- ✔ Returns first 5 rows only
- ❌ Cannot skip rows

**Using OFFSET + FETCH:**

```sql
SELECT *
FROM Employees
ORDER BY Id
OFFSET 5 ROWS
FETCH NEXT 5 ROWS ONLY;
```

- ✔ Can skip rows
- ✔ Good for pagination

# Aggregate Functions

Aggregate functions perform calculations on multiple rows and return one result.

| Function  | Purpose                 |
| --------- | ----------------------- |
| `COUNT()` | Number of rows          |
| `SUM()`   | Total of numeric column |
| `AVG()`   | Average value           |
| `MIN()`   | Smallest value          |
| `MAX()`   | Largest value           |

## COUNT()

**Count rows**

```sql
SELECT COUNT(*) FROM Orders;
```

**Count non-null column:**

- `COUNT(column_name)` counts the number of non-NULL values in that column.

```sql
SELECT COUNT(Amount) FROM Orders;
```

## SUM

- Sum values of `Amount` column across rows

```sql
SELECT SUM(Amount) FROM Orders;
```

## AVG

- Average of `Amount` column across rows

```sql
SELECT AVG(Amount) FROM Orders;
```

## MIN / MAX

- Get minimum and maximum value across rows

```sql
SELECT MIN(Amount), MAX(Amount)
FROM Orders;
```

# Grouping

## GROUP BY

- `GROUP BY` groups rows based on a column.

**Example: Total sales per customer**

```sql
SELECT CustomerName, SUM(Amount) AS TotalSales
FROM Orders
GROUP BY CustomerName;
```

🔎 **What happens?**

SQL groups rows by `CustomerName`.

**Example: Total sale by CustomerName group by year**

```sql
SELECT CustomerName,
       YEAR(CreatedAt) AS OrderYear,
       SUM(Amount) AS TotalSales
FROM Orders
GROUP BY CustomerName, YEAR(CreatedAt);
```

- All orders for the same customer in the same year are combined.
- The `SUM(Amount)` is calculated per group.

## HAVING

- `WHERE` filters rows
- `HAVING` filters groups

**Example: Customers with sales > 10,000**

```sql
SELECT CustomerName,
       SUM(Amount) AS TotalSales
FROM Orders
GROUP BY CustomerName
HAVING SUM(Amount) > 10000;
```

### WHERE vs HAVING (Interview Question)

| Feature                     | WHERE | HAVING |
| --------------------------- | ----- | ------ |
| Filters                     | Rows  | Groups |
| Used before grouping?       | ✅ Yes | ❌ No   |
| Can use aggregate function? | ❌ No  | ✅ Yes  |

**Example:**

```sql
SELECT CustomerName,
       SUM(Amount)
FROM Orders
WHERE CreatedAt >= '2026-01-01'
GROUP BY CustomerName
HAVING SUM(Amount) > 5000;
```

### GROUP BY Rules (Important)

❌ **This is invalid:**

```sql
SELECT CustomerName, Amount
FROM Orders
GROUP BY CustomerName;
```

**Why?**

👉 Every selected column must:

- Be inside aggregate function

  OR

- Be included in `GROUP BY`

### Why non-aggregated columns must be in GROUP BY

In SQL Server:

Every column in the `SELECT` list must either:

- Be inside an aggregate function (`SUM`, `COUNT`, `AVG`, etc.)
- OR appear in the `GROUP BY` clause

Because SQL must know:

👉 Which single value to show for each group

If you don't group by a column and don't aggregate it, SQL doesn't know which row's value to display.

**Example Table: Employees**

| Id | Name  | Department | Salary |
| -- | ----- | ---------- | ------ |
| 1  | Aman  | IT         | 50000  |
| 2  | Rahul | IT         | 60000  |
| 3  | Priya | HR         | 45000  |

**Invalid Query:**

```sql
SELECT Department, Name, SUM(Salary)
FROM Employees
GROUP BY Department;
```

SQL Server error:

```text
Column 'Employees.Name' is invalid in the select list because it is not contained in either an aggregate function or the 
GROUP BY clause.
```

# ALTER

`ALTER` is used to modify an existing database object.

It can modify:

- Table structure
- Columns
- Constraints
- Indexes
- Stored Procedures
- Views
- Functions
- Database properties

# 1️⃣ ALTER TABLE

## ➤ Add Column

```sql
ALTER TABLE Students
ADD Email NVARCHAR(100);
```

## ➤ Add Multiple Columns

```sql
ALTER TABLE Students
ADD Phone NVARCHAR(15),
    DateOfBirth DATE;
```

## ➤ Modify Column (Change Data Type)

```sql
ALTER TABLE Students
ALTER COLUMN StudentName NVARCHAR(200);
```

> ⚠ Cannot shrink size if data truncation occurs.

## ➤ Change NULL to NOT NULL

```sql
ALTER TABLE Students
ALTER COLUMN Email NVARCHAR(100) NOT NULL;
```

> ⚠ Column must not contain NULL values.

## ➤ Add DEFAULT Constraint

```sql
ALTER TABLE Students
ADD CONSTRAINT DF_Email
DEFAULT 'Not Provided' FOR Email;
```

## ➤ Add PRIMARY KEY

```sql
ALTER TABLE Students
ADD CONSTRAINT PK_Students
PRIMARY KEY (StudentId);
```

## ➤ Add FOREIGN KEY

```sql
ALTER TABLE Students
ADD CONSTRAINT FK_Students_Department
FOREIGN KEY (DepartmentId)
REFERENCES Departments(DepartmentId);
```

## ➤ Add UNIQUE Constraint

```sql
ALTER TABLE Students
ADD CONSTRAINT UQ_Email UNIQUE (Email);
```

## ➤ Add CHECK Constraint

```sql
ALTER TABLE Enrollments
ADD CONSTRAINT CHK_Grade
CHECK (Grade IN ('A','B','C','D','F'));
```

## ➤ Drop Column

```sql
ALTER TABLE Students
DROP COLUMN Phone;
```

## ➤ Drop Constraint

```sql
ALTER TABLE Students
DROP CONSTRAINT UQ_Email;
```

## ➤ Rename Column

```sql
EXEC sp_rename 'Students.Email', 'StudentEmail', 'COLUMN';
```

## ➤ Rename Table

```sql
EXEC sp_rename 'Students', 'UniversityStudents';
```

## ➤ Disable Constraint

```sql
ALTER TABLE Students
NOCHECK CONSTRAINT FK_Students_Department;
```

## ➤ Enable Constraint

```sql
ALTER TABLE Students
CHECK CONSTRAINT FK_Students_Department;
```

# 2️⃣ ALTER DATABASE

## ➤ Rename Database

```sql
ALTER DATABASE UniversityDB
MODIFY NAME = CollegeDB;
```

## ➤ Set Database to Read-Only

```sql
ALTER DATABASE CollegeDB
SET READ_ONLY;
```

## ➤ Set Database Back to Read-Write

```sql
ALTER DATABASE CollegeDB
SET READ_WRITE;
```

# 3️⃣ ALTER INDEX

## ➤ Rebuild Index

```sql
ALTER INDEX ALL ON Students
REBUILD;
```

## ➤ Disable Index

```sql
ALTER INDEX IX_StudentName ON Students
DISABLE;
```

# 4️⃣ ALTER VIEW

```sql
ALTER VIEW vw_StudentDetails
AS
SELECT s.StudentName, d.DepartmentName
FROM Students s
JOIN Departments d
ON s.DepartmentId = d.DepartmentId;
```

# 5️⃣ ALTER PROCEDURE

```sql
ALTER PROCEDURE GetStudents
AS
BEGIN
    SELECT * FROM Students;
END;
```

# 6️⃣ ALTER FUNCTION

```sql
ALTER FUNCTION dbo.GetStudentCount()
RETURNS INT
AS
BEGIN
    RETURN (SELECT COUNT(*) FROM Students);
END;
```

# 🚨 Important Notes

- Cannot modify column if used in index/constraint.
- Cannot drop PK if referenced by FK.
- Cannot make column NOT NULL if NULL data exists.
- Cannot directly add IDENTITY to existing column.
