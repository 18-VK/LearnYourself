# Middleware

Middleware is a software component assembled into an application pipeline to handle HTTP requests and responses. It acts as a chain, where each component can
process a request, pass it to the next component, or short-circuit the pipeline. This modular pipeline controls how an application responds to requests, with
order being crucial.

## Key Concepts of Middleware & Pipeline

- **Request/Response Handling:**
  Middleware can manipulate requests coming in and responses going out.
- **Pipeline Order:**
  The order in which components are added (usually in `Program.cs`) is the order they run for requests, and the reverse order for responses.
- **next() Delegate:**
  Each middleware receives a delegate that represents the next component, allowing it to pass control.
- **Short-circuiting:**
  A middleware can choose not to call the next component, terminating the pipeline early (e.g., authorization failure).

## Common Examples of Middleware

- **Authentication/Authorization:**
  Validating user credentials and permissions.
- **Static Files:**
  Serving files like CSS or JavaScript without running full MVC logic.
- **Routing:**
  Matching requests to specific endpoints.
- **Exception Handling:**
  Catching exceptions thrown in later stages of the pipeline.

## What middleware does

A middleware can:

- read the incoming HTTP request
- add or change headers
- log request/response details
- handle exceptions globally
- authenticate and authorize users
- compress responses
- serve static files
- rate limit requests
- decide not to pass the request further

That last part is important: middleware can stop the pipeline early.

## Why use middleware

You use middleware when the logic is cross-cutting, meaning it applies to many or all requests.

Good examples:

- logging every request
- catching unhandled exceptions
- checking authentication
- measuring performance
- adding correlation IDs for tracing
- enforcing security rules

You do not put these in every controller action because that would create duplication and inconsistent behavior.

## How middleware works internally

Each middleware gets:

- `HttpContext`
- a reference to the next middleware in the pipeline

It can do work:

- before calling `await next(context);`
- after calling `await next(context);`

So the flow looks like this:

```text
Request -> Middleware A -> Middleware B -> Middleware C -> Controller
-> Middleware C -> Middleware B -> Middleware A -> Response
```

That "before and after" pattern is the key.

# Built-in middleware examples

## UseRouting()

✅ **What it does**

It matches the incoming request URL to an endpoint (controller/action).

- It doesn't execute the controller
- It only selects the endpoint
- Stores result in `HttpContext`

📌 **When to use**

Always in Web API (unless using minimal APIs differently).

Without it:
ASP.NET doesn't know where to send the request.

💻 **How to use**

```csharp
app.UseRouting();
```

⚠️ **Important**

Must come before authentication/authorization because they need endpoint info.

## UseAuthentication()

✅ **What it does**

- Reads token (JWT, cookies, etc.)
- Validates it
- Creates `HttpContext.User`

👉 It identifies WHO the user is

📌 **When to use**

- When your API has login/users
- JWT-based APIs (most common)
- Role-based systems

💻 **How to use**

**Step 1: Register service**

```csharp
builder.Services.AddAuthentication("Bearer")
    .AddJwtBearer("Bearer", options =>
    {
        options.Authority = "https://your-auth-server";
        options.Audience = "your-api";
    });
```

**Step 2: Add middleware**

```csharp
app.UseAuthentication();
```

⚠️ **Important**

- Must come before `UseAuthorization()`
- Doesn't block requests by itself

## UseAuthorization()

✅ **What it does**

- Checks if user is allowed to access endpoint
- Uses `[Authorize]` attributes

👉 It answers: "Can this user access this resource?"

📌 **When to use**

- Role-based access
- Secure APIs

**Example:**

```csharp
[Authorize]
[Authorize(Roles = "Admin")]
```

💻 **How to use**

```csharp
builder.Services.AddAuthorization();
app.UseAuthorization();
```

⚠️ **Important**

- Must come after `UseAuthentication()`
- Requires routing info → so after `UseRouting()`

## UseExceptionHandler()

✅ **What it does**

- Catches unhandled exceptions
- Prevents app crash
- Returns safe response

👉 Global error handling

📌 **When to use**

Always in production APIs.

Without it:

- Users may see raw exception
- App may crash or leak sensitive data

💻 **How to use**

```csharp
app.UseExceptionHandler("/error");
```

**Example: controller**

```csharp
[ApiController]
public class ErrorController : ControllerBase
{
    [Route("/error")]
    public IActionResult HandleError()
    {
        return Problem("Something went wrong");
    }
}
```

🔥 **Production tip**

Better approach:
👉 Custom middleware for Global exception handling

⚠️ **Order**

Must be FIRST in pipeline.

## UseStaticFiles()

✅ **What it does**

- Serves files from `wwwroot` folder:
  images, CSS, JS, HTML

📌 **When to use**

- Web apps (frontend + backend together)
- Not needed for pure APIs (mostly)

💻 **How to use**

```csharp
app.UseStaticFiles();
```

**Folder:**

```text
wwwroot/
   logo.png
```

**Access:**

```text
https://yourapi.com/logo.png
```

⚠️ **Important**

- Should come early
- Can bypass controller pipeline (fast)

## UseCors()

✅ **What it does**

- Controls Cross-Origin Resource Sharing

👉 Allows frontend (React, Angular, etc.) to call your API

📌 **When to use**

If:

- Frontend runs on different domain/port

**Example:**

```text
API: api.com
Frontend: localhost:3000
```

💻 **How to use**

**Step 1: Configure**

```csharp
builder.Services.AddCors(options =>
{
    options.AddPolicy("AllowFrontend",
        policy =>
        {
            policy.WithOrigins("http://localhost:3000")
                  .AllowAnyHeader()
                  .AllowAnyMethod();
        });
});
```

**Step 2: Use middleware**

```csharp
app.UseCors("AllowFrontend");
```

⚠️ **Order**

Must be before endpoints:

```csharp
app.UseCors();
app.MapControllers();
```

## UseRateLimiter()

✅ **What it does**

- Limits number of requests per user/IP

👉 Prevents:

- abuse
- DDoS
- brute force

📌 **When to use**

- Public APIs
- Login endpoints
- Payment APIs

💻 **How to use (.NET 7+)**

**Step 1: Configure**

```csharp
builder.Services.AddRateLimiter(options =>
{
    options.AddFixedWindowLimiter("fixed", opt =>
    {
        opt.PermitLimit = 5;
        opt.Window = TimeSpan.FromSeconds(10);
        opt.QueueLimit = 2;
    });
});
```

**Step 2: Use middleware**

```csharp
app.UseRateLimiter();
```

**Step 3: Apply**

```csharp
[EnableRateLimiting("fixed")]
```

# Final Production Order (VERY IMPORTANT)

Here's how a real-world pipeline should look:

```csharp
app.UseExceptionHandler();     // 1. Catch errors first

app.UseStaticFiles();          // 2. Serve static files fast

app.UseRouting();              // 3. Match endpoint

app.UseCors("AllowFrontend");  // 4. Allow frontend

app.UseAuthentication();       // 5. Identify user
app.UseAuthorization();        // 6. Check access

app.UseRateLimiter();          // 7. Protect API

app.MapControllers();          // 8. Execute endpoint
```
